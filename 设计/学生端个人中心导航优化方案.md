## 1. 现状分析与根因

### 1.1 问题描述

学生门户"个人中心"存在严重的导航断裂问题：Tab 导航栏（基本资料/教育经历/简历附件/实习项目/技能证书/社团经历/隐私设置）仅在 `/profile` 路由可见。点击任意 Tab 跳转到子页面后（如 `/profile/education`），Tab 栏立即消失，学生必须通过 PortalHeader 的"个人中心"入口返回主页才能切换功能模块。

学生端以**手机操作为主**（大部分学生在手机上填写资料和上传文件），7 个 Tab 在移动端小屏幕上频繁的"前进-返回"操作意味着大量不必要的页面跳转，每一次返回都需要重新加载 ProfileView 及其数据，体验极差。

### 1.2 根因：平铺路由导致父组件被卸载

当前路由配置（`code/recruit-portal-ui/src/router/index.js`）将个人中心的所有子页面定义为**同级的顶层路由**：

```js
{ path: '/profile',             name: 'profile',    component: () => import('../views/ProfileView.vue') },      // Tab 栏在此
{ path: '/profile/education',   name: 'education',  component: () => import('../views/EducationView.vue') },     // 独立页面，无 Tab
{ path: '/profile/resume',      name: 'resume',     component: () => import('../views/ResumeUploadView.vue') },  // 独立页面，无 Tab
{ path: '/profile/internship',  name: 'internship', component: () => import('../views/ProfileExtraView.vue') }, // 独立页面，无 Tab
{ path: '/profile/certificate', name: 'certificate',component: () => import('../views/ProfileExtraView.vue') }, // 独立页面，无 Tab
{ path: '/profile/activity',    name: 'activity',   component: () => import('../views/ProfileExtraView.vue') }, // 独立页面，无 Tab
```

Vue Router 在处理路由切换时，将 `/profile` → `/profile/education` 视为**两个不同顶层路由之间的跳转**：
1. `ProfileView` 组件（含 Tab 栏）被 `onUnmounted` 销毁
2. `EducationView` 组件被创建并挂载到根 `<router-view>`
3. Tab 栏随 `ProfileView` 一起消失在 DOM 中

虽然 URL 路径看起来有层级关系（`/profile/education` 是 `/profile` 的子路径），但路由表中没有定义父子关系（缺少 `children`），Vue Router 完全不知道它们应该共享父组件。

### 1.3 App.vue 根布局分析

```html
<!-- App.vue -->
<router-view v-slot="{ Component }">
  <transition name="fade" mode="out-in">
    <component :is="Component" />
  </transition>
</router-view>
```

整个应用只有一个顶层 `<router-view>`。所有页面组件（HomeView、JobListView、ProfileView、EducationView 等）都在此渲染，切换时旧组件被完全替换。这是标准 SPA 架构，但对于"需要持久化导航栏"的个人中心场景，需要在 ProfileView **内部**增加第二个 `<router-view>` 来承载子页面。

## 2. 业界最佳实践调研

### 2.1 Vue Router 嵌套路由模式

Vue Router 4 官方推荐的嵌套路由方案是 `children` + 父组件内嵌 `<router-view>`，这正是解决本问题的标准模式。

**核心机制**：
- 父路由定义 `children` 数组，每个子路由的 `path` 是相对于父路由的
- 父组件模板中放置 `<router-view>` 作为子组件的渲染插槽
- 子路由切换时，父组件**保持挂载**，只有 `<router-view>` 内的子组件被替换
- URL 结构保持 `/parent/child1` → `/parent/child2` 的语义，浏览器后退/前进正常工作

**官方示例（Vue Router 4 文档）**：
```js
const routes = [
  {
    path: '/user/:id',
    component: User,
    children: [
      { path: '', component: UserHome },
      { path: 'profile', component: UserProfile },
      { path: 'posts', component: UserPosts },
    ],
  },
]
```

在 `User.vue` 模板中：
```html
<template>
  <div class="user">
    <h2>User {{ $route.params.id }}</h2>
    <!-- 子路由渲染在此，User 组件不会被销毁 -->
    <router-view />
  </div>
</template>
```

**与 keep-alive 配合**：若需要缓存子组件状态避免数据重复加载，在父组件的 `<router-view>` 外包裹 `<keep-alive>`：
```html
<router-view v-slot="{ Component }">
  <keep-alive>
    <component :is="Component" />
  </keep-alive>
</router-view>
```

**路由守卫兼容性**：
- 子路由自动继承父路由的 `meta` 属性（包括 `meta.requiresAuth`）
- `router.beforeEach` 对所有路由（父+子）统一生效，无需修改守卫逻辑
- `beforeRouteUpdate` 在父组件内可用于监听子路由变化

### 2.2 移动端 Tab 横向滚动模式

移动端 Tab 栏横向滚动的业界标准实践：

| 方案 | 优点 | 缺点 |
|------|------|------|
| CSS `overflow-x: auto` + 隐藏滚动条 | 零 JS、原生滚动性能、触摸惯性 | 无法精细控制 active 指示器动画 |
| JS 驱动 `transform: translateX` | 完全控制动画曲线 | 需自己处理触摸事件、惯性 |
| **混合方案（推荐）** | CSS 原生滚动 + JS 驱动指示器 + scrollIntoView | 实施复杂度适中 |

**触摸目标规范**：
- iOS HIG：最小触摸目标 44x44pt
- Material Design：最小触摸目标 48x48dp
- 本项目目标：Tab 高度 >= 44px，左右 padding >= 16px，确保点击区域充足

**CSS Scroll Snap 增强（可选升级）**：CSS `scroll-snap-type: x mandatory` + `scroll-snap-align: start` 可提供原生级 Tab snap 效果，比纯 overflow 滚动更流畅。首期可先用 `overflow-x: auto`，后续按需升级。

**iOS 18 兼容性警告**：`-webkit-overflow-scrolling: touch` 在 iOS 18.3+ 中已被移除。当前项目使用的此属性在新版 Safari 中被静默忽略（不报错），应依赖标准 `overflow: auto` + `scroll-behavior: smooth` 作为主要滚动机制，保留 `-webkit-overflow-scrolling: touch` 仅为旧设备渐进增强。

**底部安全区前置条件**：`env(safe-area-inset-*)` 生效需要 `<meta name="viewport" content="..., viewport-fit=cover">`。需确认 `index.html` 中已包含此声明（本项目大概率已配置，但改造前应验证）。

**底部安全区**：使用 `env(safe-area-inset-bottom)` 和 CSS 变量 `var(--safe-bottom)`（项目已配置）。

### 2.3 行业参考

**Boss 直聘移动端**：个人中心采用固定顶部 Tab 栏 + Swipe 切换内容区，Tab 栏有横向滚动和滑动指示器。**本项目不引入 Swiper 库**，使用 CSS 原生滚动实现。

**Vue Storefront 2**：大量使用嵌套路由实现多级导航，父组件持久化 Header/Sidebar，子组件在 `<router-view>` 中渲染。与本方案场景高度一致。

**Element Plus 官网**：使用嵌套路由实现文档的左侧导航 + 右侧内容布局，左侧导航栏在路由切换时保持可见。

### 2.4 调研结论

Vue Router `children` + 嵌套 `<router-view>` 是业界标准方案，与本项目场景完美匹配：
- 改动集中在路由配置和 ProfileView 组件，子页面组件**零改动或微小改动**
- URL 结构、路由守卫、浏览器历史行为完全保持原样
- 无任何第三方依赖引入

## 3. 架构方案：嵌套路由改造

### 3.1 方案选型

经过对两种可行方案的对比分析：

| 维度 | 方案A：Vue Router children（推荐） | 方案B：Tab 栏提升到 App.vue |
|------|----------------------------------|---------------------------|
| 改动范围 | router/index.js + ProfileView.vue | App.vue + ProfileView.vue |
| 组件生命周期 | ProfileView 只挂载一次，子组件在 router-view 内切换 | 无组件复用问题，但 Tab 栏逻辑侵入 App.vue |
| 路由语义 | 真实的父子关系，URL 结构 = 组件树结构 | 路由仍是平铺的，Tab 栏是条件渲染的"假象" |
| 可扩展性 | 新增子页面只需在 children 中添加一条 | 新增子页面需同步修改 App.vue 的条件判断 |
| 过渡动画 | 子路由切换只在内部 router-view 触发，不影响外部 | 两层 router-view 都触发过渡，需额外处理 |
| 代码清晰度 | 路由配置即文档，一目了然 | Tab 栏渲染条件散落在 App.vue 中，非显式 |

**推荐方案 A（Vue Router children）**，理由：
1. 改动量更小（仅 2 个文件），且改动集中在个人中心域，不污染 App.vue
2. 路由配置自文档化——看 `children` 就知道个人中心有哪些子页面
3. 组件生命周期符合直觉——父组件负责持久化 UI（Tab 栏），子组件负责业务内容
4. Vue Router 原生支持，无 hack

### 3.2 路由配置变更

**改造后的路由配置**（`router/index.js`）：

```js
// ===== 改造前：6 条独立顶层路由 =====
{ path: '/profile',             name: 'profile',    meta: { requiresAuth: true }, component: () => import('../views/ProfileView.vue') },
{ path: '/profile/education',   name: 'education',  meta: { requiresAuth: true }, component: () => import('../views/EducationView.vue') },
{ path: '/profile/resume',      name: 'resume',     meta: { requiresAuth: true }, component: () => import('../views/ResumeUploadView.vue') },
{ path: '/profile/internship',  name: 'internship', meta: { requiresAuth: true }, component: () => import('../views/ProfileExtraView.vue'), props: { type: 'internship' } },
{ path: '/profile/certificate', name: 'certificate',meta: { requiresAuth: true }, component: () => import('../views/ProfileExtraView.vue'), props: { type: 'certificate' } },
{ path: '/profile/activity',    name: 'activity',   meta: { requiresAuth: true }, component: () => import('../views/ProfileExtraView.vue'), props: { type: 'activity' } },

// ===== 改造后：1 条父路由 + 5 条子路由 =====
{
  path: '/profile',
  name: 'profile',
  component: () => import('../views/ProfileView.vue'),
  meta: { requiresAuth: true },
  children: [
    // path: '' 不定义组件——基本资料在 ProfileView 内联渲染，路由保持 /profile
    {
      path: 'education',
      name: 'education',
      meta: { requiresAuth: true },
      component: () => import('../views/EducationView.vue'),
    },
    {
      path: 'resume',
      name: 'resume',
      meta: { requiresAuth: true },
      component: () => import('../views/ResumeUploadView.vue'),
    },
    {
      path: 'internship',
      name: 'internship',
      meta: { requiresAuth: true },
      component: () => import('../views/ProfileExtraView.vue'),
      props: { type: 'internship' },
    },
    {
      path: 'certificate',
      name: 'certificate',
      meta: { requiresAuth: true },
      component: () => import('../views/ProfileExtraView.vue'),
      props: { type: 'certificate' },
    },
    {
      path: 'activity',
      name: 'activity',
      meta: { requiresAuth: true },
      component: () => import('../views/ProfileExtraView.vue'),
      props: { type: 'activity' },
    },
  ],
},
```

**变更说明**：
- 6 条独立顶层路由 → 删减为 0 条；1 条父路由 `children[5]` → 新增。
- 父路由的 `meta.requiresAuth` 被子路由继承，`router.beforeEach` 无需任何修改。
- 路由 `name` 保持不变（`education`、`resume`、`internship`、`certificate`、`activity`），确保 `PortalHeader.vue` 等引用 `route.name` 的地方无需改动。
- `path: ''` 不定义组件——当 URL 为 `/profile` 时，内层 `<router-view>` 无匹配子组件，不渲染任何内容，ProfileView 展示内联的基本资料表单。
- **隐私设置**保持现状：不作为子路由，在 ProfileView 内通过本地 `activeTab` 变量切换，点击时 `@click.prevent` 阻止导航。

### 3.3 ProfileView 改造概要

改造前结构（伪代码）：
```
ProfileView
├── Tab 栏（<router-link> 跳转到独立路由）
├── [v-if] 基本资料表单（activeTab === 'basic'）
├── [v-if] 隐私设置面板（activeTab === 'privacy'）
└── （子页面在外部独立路由中渲染，ProfileView 被卸载）
```

改造后结构（伪代码）：
```
ProfileView
├── Tab 栏（<router-link> 跳转到子路由，active 状态由 route.path 派生）
├── Tab 指示器（独立绝对定位元素，CSS transition 动画）
├── [v-if] 基本资料表单（route.path === '/profile'，无激活子路由时展示）
├── [v-if] 隐私设置面板（本地 activeTab === 'privacy'，不改变 URL）
└── <router-view>（子路由组件在此渲染：EducationView / ResumeUploadView / ProfileExtraView）
```

**关键变化**：
1. `activeTab` 从 `ref('basic')` 改为**计算属性**（从 `route.path` 派生），`watch(route)` 替代 `onMounted` 中的路径判断
2. 新增 `<router-view>` 承载子路由组件
3. Tab 栏的 `<router-link>` 的 `active` 状态改用 `route.name` 匹配，不再依赖 `activeTab` 变量
4. Tab 指示器从 `border-bottom` 改为独立的 `<div class="tab-indicator">`（绝对定位 + transition）

### 3.4 子页面组件改动评估

| 子组件 | 是否需要改动 | 原因 |
|--------|------------|------|
| EducationView.vue | **否** | 独立组件，通过 API 加载数据，不依赖 ProfileView 任何状态 |
| ResumeUploadView.vue | **否** | 同上 |
| ProfileExtraView.vue | **是（微小）** | 三个路由共享同一组件，需确保路由切换时组件正确重新初始化。改用父级 `<router-view>` 的 `:key="route.path"` 或组件内 `watch(() => route.path)` 响应路由变化 |
| PortalHeader.vue | **否** | 无改动——路由 `name` 不变，"个人中心"入口始终指向 `/profile` |
| App.vue | **否** | 无改动——顶层 `<router-view>` 只感知顶层路由变化，`/profile` → `/profile/education` 不触发顶层路由切换 |

### 3.5 过渡动画处理

**App.vue 层**：顶层 `<transition name="fade" mode="out-in">` 保持不变。当从 `/jobs` 切换到 `/profile`（或 `/profile/education`）时，整个 ProfileView 执行 fade 进出动画。在 `/profile` 内部子路由切换时（如 `/profile/education` → `/profile/resume`），顶层路由不变，**不触发 App.vue 的过渡**。

**ProfileView 层**：在内层 `<router-view>` 上添加轻量过渡：
```html
<router-view v-slot="{ Component, route }">
  <transition name="fade" mode="out-in">
    <component :is="Component" :key="route.path" />
  </transition>
</router-view>
```

`:key="route.path"` 确保 ProfileExtraView 在三个路由间切换时强制重新创建组件实例，避免状态残留。

### 3.6 路由守卫兼容性验证

改造前后对比：

| 场景 | 改造前 | 改造后 | 是否兼容 |
|------|--------|--------|---------|
| 未登录访问 `/profile/education` | beforeEach 拦截，跳转 login | beforeEach 拦截，跳转 login（子路由继承 `meta.requiresAuth`） | 是 |
| 未登录访问 `/profile` | beforeEach 拦截 | beforeEach 拦截 | 是 |
| 登录后直接访问 `/profile/resume` | 正常渲染 ResumeUploadView | 正常渲染 ProfileView + ResumeUploadView（子路由） | 是 |
| redirect 参数回跳 | `?redirect=/profile/education` → 登录后跳转 | 完全相同 | 是 |
| 浏览器后退 `/profile/education` → `/profile` | ProfileView 重新挂载 | ProfileView **保持挂载**，子路由切换 | 是（更优——数据不丢失） |

### 3.7 组件生命周期影响

| 生命周期钩子 | 改造前行为 | 改造后行为 | 风险 |
|-------------|-----------|-----------|------|
| ProfileView `onMounted` | 每次进入 `/profile` 触发 | 仅在**首次**进入 `/profile` 时触发 | **低**——`loadProfile()` 在改造后仅调用一次，若需响应路由变化刷新，改用 `watch(route)` |
| ProfileView `onUnmounted` | 离开 `/profile` 时触发 | 离开个人中心域（如去 `/jobs`）时触发 | 无变化 |
| EducationView `onMounted` | 每次进入触发 | 每次进入触发（子路由切换时重新挂载） | 无变化 |
| ProfileExtraView `onMounted` | 每次进入触发 | 每次进入触发（`:key="route.path"` 确保重新挂载） | 无变化 |
| `beforeRouteUpdate` | 不适用 | ProfileView 可选用此守卫监听子路由变化 | 新增可选优化点 |

## 4. 移动端交互设计

### 4.1 Tab 栏组件结构

```
┌─ .tabs-scroll-container ────────────────────────────────────────┐
│ ┌─ .tabs (display: flex; position: relative) ────────────────┐ │
│ │  [基本资料]  [教育经历]  [简历附件]  [实习/项目]  [技能证书] ... │ │
│ │  ━━━━━━                                                      │ │
│ │  ▲ .tab-indicator (position: absolute; bottom: 0)            │ │
│ └──────────────────────────────────────────────────────────────┘ │
│ ◄────────── 横向可滚动 ──────────►                                │
└──────────────────────────────────────────────────────────────────┘
```

**设计要点**：
- 外层 `.tabs-scroll-container`：`overflow-x: auto`，提供原生横向滚动
- 内层 `.tabs`：`display: flex; position: relative`，Tab 项弹性排列，指示器相对于此定位
- `.tab-indicator`：独立 `<div>`，绝对定位在 `.tabs` 底部，`left` 和 `width` 通过 JS 动态计算，CSS transition 实现平滑动画
- 每个 Tab 最小触摸高度 44px，使用 `flex-shrink: 0` 防止被压缩

### 4.2 完整 CSS 样式

```css
/* ===== Tab 滚动容器（移动端适配） ===== */
.tabs-scroll {
  position: relative;
  margin-bottom: 24px;
  /* 移动端横向滚动 */
  overflow-x: auto;
  overflow-y: hidden;
  -webkit-overflow-scrolling: touch;
  scrollbar-width: none;          /* Firefox */
  -ms-overflow-style: none;       /* IE/Edge */
  /* 顶部 sticky 时需考虑刘海屏 */
  padding-top: env(safe-area-inset-top, 0px);
}
.tabs-scroll::-webkit-scrollbar {
  display: none;                  /* Chrome/Safari */
}

/* ===== Tab 列表（flex 容器） ===== */
.tabs {
  display: flex;
  position: relative;
  border-bottom: 1px solid var(--color-border);
  /* no gap — 指示器宽度基于 offsetLeft+offsetWidth，gap 会导致计算偏差 */
}

/* ===== 单个 Tab ===== */
.tab {
  position: relative;
  flex-shrink: 0;
  display: flex;
  align-items: center;
  justify-content: center;
  min-height: 44px;               /* iOS HIG 最小触摸目标 */
  padding: 12px 18px;
  font-size: 14px;
  font-weight: 400;
  color: var(--color-text-secondary);
  text-decoration: none;
  white-space: nowrap;
  cursor: pointer;
  user-select: none;
  -webkit-user-select: none;
  -webkit-tap-highlight-color: transparent;
  transition: color 0.2s ease;
}
.tab:hover {
  color: var(--color-text);
}
.tab:active {
  /* 触摸反馈 */
  background: rgba(95, 184, 214, 0.08);
  transition: background 0.05s;
}
.tab--active {
  color: var(--color-primary);
  font-weight: 600;
}

/* ===== Active 指示器（独立元素，CSS transition 动画） ===== */
.tab-indicator {
  position: absolute;
  bottom: -1px;                   /* 覆盖 .tabs 的 border-bottom */
  left: 0;
  height: 3px;
  background: var(--color-primary);
  border-radius: 2px 2px 0 0;
  pointer-events: none;           /* 不阻挡 Tab 点击 */
  transition: left 0.3s cubic-bezier(0.4, 0, 0.2, 1),
              width 0.3s cubic-bezier(0.4, 0, 0.2, 1);
```

### 4.3 Active 指示器动画机制

**原理**：不使用 CSS `border-bottom`（无法做动画），改用独立的 `.tab-indicator` 元素。JS 监听路由变化，计算当前激活 Tab 的 `offsetLeft` 和 `offsetWidth`，更新指示器的 `left` 和 `width`。CSS `transition` 负责平滑动画。

**JS 逻辑**（ProfileView `<script setup>` 中）：

```js
import { ref, computed, watch, onMounted, nextTick } from 'vue';
import { useRoute } from 'vue-router';

const route = useRoute();
const tabsRef = ref(null);

// 指示器样式
const indicatorStyle = ref({
  left: '0px',
  width: '0px',
});

/** 根据当前路由判断激活的 Tab 标识 */
const activeTab = computed(() => {
  const name = route.name;
  if (name === 'education') return 'education';
  if (name === 'resume') return 'resume';
  if (name === 'internship') return 'internship';
  if (name === 'certificate') return 'certificate';
  if (name === 'activity') return 'activity';
  // /profile 根路径，区分基本资料和隐私设置
  return localPrivacyActive.value ? 'privacy' : 'basic';
});

/** 更新指示器位置 + 自动滚动到可见 */
function updateIndicator() {
  if (!tabsRef.value) return;
  const selector = activeTab.value === 'basic' || activeTab.value === 'privacy'
    ? '.tab--home'   // 基本资料和隐私设置 Tab 都指向 /profile
    : `.tab--${activeTab.value}`;
  const activeEl = tabsRef.value.querySelector(`.tab--active, ${selector}`);
  if (!activeEl) return;

  // 更新指示器
  indicatorStyle.value = {
    left: `${activeEl.offsetLeft}px`,
    width: `${activeEl.offsetWidth}px`,
  };

  // 移动端自动滚动到可视区
  if (window.innerWidth <= 767) {
    activeEl.scrollIntoView({
      behavior: 'smooth',
      block: 'nearest',
      inline: 'center',
    });
  }
}

// 路由变化时更新
watch(() => route.path, () => {
  nextTick(updateIndicator);
});

onMounted(() => {
  nextTick(updateIndicator);
});
```

**注意**：基本资料和隐私设置的 `<router-link>` 都指向 `/profile`（`to="/profile"`），在 Tab 元素上需通过其他方式区分。推荐方案：给基本资料和隐私设置的 Tab 各加一个 `data-tab` 属性，通过 `data-tab` 选择器定位。

### 4.6 边界情况处理

| 边界情况 | 处理方式 |
|---------|---------|
| 7 个 Tab 全部可见（平板横屏） | `flex-shrink: 0` + `overflow-x: auto`，不需要滚动时容器正常显示 |
| 仅 3-4 个 Tab 可见（手机竖屏） | 横向滚动，隐藏滚动条，`scrollIntoView` 自动将选中 Tab 居中 |
| 用户手动滑动 Tab 栏 | 原生滚动行为，不干扰选中状态 |
| 快速连续点击多个 Tab | CSS transition 自动跟随——每次路由变化触发 `updateIndicator()`，指示器平滑过渡到新位置 |
| iOS Safari 弹性滚动（rubber-banding） | `-webkit-overflow-scrolling: touch` 提供原生惯性滚动 |
| 从外部路由进入 `/profile/education` | `onMounted` 时调用 `updateIndicator()`，指示器定位到教育经历 Tab |
| 浏览器窗口旋转 | 指示器位置基于 `offsetLeft`（实时计算），窗口大小变化后下次 `updateIndicator()` 自动修正 |
| 系统动效降级（`prefers-reduced-motion: reduce`） | CSS 中 `transition: none` 覆盖动画，JS 中 `scroll-behavior: smooth` 被浏览器自动忽略 |

### 4.7 隐私设置特殊处理

当前隐私设置与基本资料共用 `/profile` 路由。改造后隐私设置保持为 ProfileView 内的本地状态：
- 点击"隐私设置"Tab 时 `@click.prevent` 阻止路由导航，设置本地 `localPrivacyActive = true`
- URL 保持 `/profile` 不变
- **已知局限**：浏览器前进/后退到 `/profile` 时，若之前处于隐私设置状态，会丢失并回退到基本资料。建议后续将隐私设置独立为 `/profile/privacy` 子路由。

**脚本关键新增/改动**：

```js
import { ref, reactive, computed, watch, onMounted, nextTick } from 'vue';
import { useRoute, useRouter } from 'vue-router';

const route = useRoute();
const router = useRouter();

const tabsRef = ref(null);

// 隐私设置本地状态（不改变 URL）
const localPrivacyActive = ref(false);

// 路由名称简写
const routeName = computed(() => route.name);

// 是否展示基本资料或隐私设置（无激活子路由）
const showBasicInfo = computed(() => {
  return !localPrivacyActive.value &&
    (!routeName.value || routeName.value === 'profile');
});

// 是否展示子路由
const showChildRoute = computed(() => {
  return !localPrivacyActive.value &&
    routeName.value && routeName.value !== 'profile';
});

// 基本资料/隐私设置 Tab 是否 active
const isBasicOrPrivacyTab = computed(() => {
  return routeName.value === 'profile' || !routeName.value;
});

// 指示器位置
const indicatorLeft = ref(0);
const indicatorWidth = ref(0);

function switchToPrivacy() {
  localPrivacyActive.value = true;
  // 确保 URL 回到 /profile
  if (route.path !== '/profile') {
    router.replace('/profile');
  }
  nextTick(updateIndicator);
}

/** 更新指示器位置 */
function updateIndicator() {
  if (!tabsRef.value) return;
  const selector = localPrivacyActive.value
    ? '[data-tab="privacy"]'
    : routeName.value === 'profile' || !routeName.value
      ? '[data-tab="home"]'
      : `.tab--active`;
  const activeEl = tabsRef.value.querySelector(selector);
  if (!activeEl) return;

  // offsetLeft 相对于 offsetParent，需补偿横向滚动偏移（移动端）
  const scrollContainer = tabsRef.value.parentElement; // .tabs-scroll
  const scrollOffset = scrollContainer ? scrollContainer.scrollLeft : 0;
  indicatorLeft.value = activeEl.offsetLeft - scrollOffset;
  indicatorWidth.value = activeEl.offsetWidth;

  // 移动端自动滚动到视野中央
  if (window.innerWidth <= 767) {
    activeEl.scrollIntoView({ behavior: 'smooth', block: 'nearest', inline: 'center' });
  }
}

// 路由变化 → 退出隐私模式 + 更新指示器 + 滚动到顶部 + 刷新数据
watch(() => route.path, (newPath) => {
  if (newPath !== '/profile') {
    localPrivacyActive.value = false;
  } else {
    // 回到基本资料 Tab 时重新加载个人信息（可能在子 Tab 中修改了关联数据）
    loadProfile();
  }
  // Tab 切换时滚动到页面顶部，避免停留在上一页的滚动位置
  window.scrollTo({ top: 0, behavior: 'instant' });
  nextTick(updateIndicator);
});

// 监听隐私设置状态 → 更新指示器
watch(localPrivacyActive, () => {
  nextTick(updateIndicator);
});

onMounted(() => {
  loadProfile();
  nextTick(updateIndicator);
});
```

```js
  window.scrollTo({ top: 0, behavior: 'instant' });
  nextTick(updateIndicator);
});
```

> 本章记录三个子 Agent（Researcher / SystemArchitect / InterfaceDesigner）的产出整合过程，以及其间发现的矛盾与裁决。

### 9.1 矛盾裁决记录

| 类型 | 涉及Agent | 描述 | 裁决 | 理由 |
|------|----------|------|------|------|
| VARIANCE | Researcher vs SystemArchitect | `meta.requiresAuth` 继承行为——Researcher 警告 meta 不自动继承需逐子路由声明，SystemArchitect 确认子路由继承父路由 meta | **以 SystemArchitect + Vue Router 4 官方文档为准** | Vue Router 4 官方文档明确：meta 字段从父路由浅合并到子路由。`beforeEach` 中 `to.meta.requiresAuth` 能正确读取父路由的值 |
| VARIANCE | SystemArchitect vs InterfaceDesigner | keep-alive 使用时机——InterfaceDesigner 建议启用，SystemArchitect 建议第一阶段不用 | **以 SystemArchitect 为准** | 第一阶段保持与改造前行为一致（子组件每次切换销毁重建），降低风险。keep-alive 存在已知 bug（vuejs/core#12786）且需要子组件适配 `onActivated` |
| VARIANCE | SystemArchitect | 建议拆分 ProfileBasicView / ProfilePrivacyView 为独立子组件文件 | **不拆分** | 遵循用户要求"改动最小化"。基本资料和隐私设置保留在 ProfileView 内联渲染。文档中已注明此设计权衡及后续优化建议 |
| VARIANCE | InterfaceDesigner + Researcher | `scroll-snap-type` 是否在首期引入 | **作为可选增强** | 首期先用 `overflow-x: auto`（项目已有），后续按需升级。文档中已注明升级路径 |
