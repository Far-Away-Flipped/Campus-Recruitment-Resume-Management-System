### 1.2 获取 hr_director 测试 Token

登录接口 `POST /api/admin/auth/login` 需要图形验证码，无法用纯 curl 一步完成（验证码是随机生成并存入服务端 Caffeine 缓存，无法脱离浏览器流程预测）。因此 Token 获取采用"浏览器登录 + 复制 localStorage"的方式：

1. 浏览器打开 `http://127.0.0.1:5174`（或直接 `http://127.0.0.1:8080` 如有独立入口），用种子账号 `admin` / `admin123` 登录
2. 按 F12 打开开发者工具 → Application/应用 → Local Storage → 找 `admin_token` 键，复制其值
3. 该 Token 有效期 30 分钟（`application.yml`：`jwt.admin.expiration: 30`），过期需重新登录复制

后续命令中的 `<HR_DIRECTOR_TOKEN>` 均指此值。

### 1.3 创建 hr_recruiter 测试账号（权限隔离测试的前置依赖）

### 1.4 curl 命令模板约定

- Base URL 统一用 `http://127.0.0.1:8080`（**不是** `http://127.0.0.1:5174`，除非该用例明确标注为"经Vite代理"）
- 请求体 JSON 统一用双引号并对内部双引号转义 `\"`，这种写法在 `curl.exe` 下 PowerShell / Git Bash 均可直接使用
- 鉴权头：`-H "Authorization: Bearer <TOKEN>"`
- 查看响应头（验证CORS头是否存在）必须加 `-i`（包含响应头）而非只用 `-s`（仅响应体）

## 5. 高风险点清单（关键门禁，不过说明有严重问题）

以下用例失败代表**严重安全或功能问题**，任何一条不过都应立即停止后续验收并升级处理：

1. **C1-02 / C1-09**（恶意Origin被放行）：说明遗留的 `ResourcesConfig.java` 通配符配置未被真正清理，或以其他形式重新引入——退化为"任意网站可携带用户凭证跨站请求"，比原始故障"手机连不上"严重得多。
2. **C1-05**（域名Origin触发了CIDR匹配）：说明实现引入了DNS解析或字符串误判逻辑，存在SSRF/DNS重绑定攻击面。
3. **C2-06**（通配符提交未被拦截，或拦截顺序错误导致返回70003而非70002）：说明校验逻辑被改动破坏，通配符+凭证组合可能重新进入生产。
4. **C2-09 / C2-10**（CIDR范围校验失效）：说明HR可以通过管理界面把整个公网段甚至 `0.0.0.0/0` 加入白名单，攻击面从"局域网"扩大到"互联网任意站点"。
5. **C2-13**（内置规则可被物理删除）：`campus.atmoto.cn` 主域名规则一旦被误删且无保护，门户前端将全面跨域失败。
6. **C2-22 / C2-23**（权限隔离失效）：`hr_recruiter` 能执行写操作，意味着任何招聘专员账号被盗用即可修改CORS白名单，权限模型形同虚设。
7. **C3-06**（诊断接口敏感信息泄露）：JWT密钥/DB连接串一旦泄露，攻击者可伪造Token或直接连接数据库，属于最高等级安全事件。
8. **C4-01~C4-05**（匿名访问未被拒绝）：整个网络管理模块的鉴权边界失守，等同于"任何人都能改CORS白名单"。
9. **C5-02 / C5-03 / C5-04**（直连8080测试链路本身）：如果这几条测不出真实差异（比如无论加不加白名单都放行/都拒绝），说明 `DynamicCorsConfigurationSource` 根本没有接管CORS判定，整个动态白名单机制未生效，退回到故障发生前的状态。
10. **C6-06**（Maven编译失败/循环依赖）：说明模块归属违反了方案裁决1的依赖方向约束，是架构层面的硬故障，不是运行时问题。
