# 校园招聘简历管理系统 使用说明

> 版本：V3.1  ｜  编制日期：2026-08-13  ｜  遨天科技（北京）有限公司

---

## 一、系统概述

### 1.1 系统简介

校园招聘简历管理系统是遨天科技（北京）有限公司人文发展部（HR 部门）使用的校招全流程管理平台。系统包含三个端：

| 端 | 用户 | 访问地址（开发环境） | 主要功能 |
|----|------|-------------------|---------|
| **学生门户** | 求职学生 | `http://localhost:5173` | 注册登录、浏览岗位、投递简历、查看进度、消息通知 |
| **HR 管理后台** | 超级管理员 / HR 用户 | `http://localhost:5174/admin` | 岗位管理、简历筛选、数据报表、个人中心 |
| **系统管理端** | 超级管理员 | 与 HR 后台共用入口 | 用户权限、组织架构、品牌配置、网络配置、操作审计 |

### 1.2 技术架构

- **后端**：Spring Boot 3.4 + Java 17，单 JAR 部署，端口 8080
- **前端**：Vue 3 + Vite，学生端（5173）和 HR 端（5174）独立工程
- **数据库**：MySQL 8.0，库名 `atmoto_recruit`
- **缓存**：Caffeine 本地缓存（无 Redis 依赖）
- **部署**：单台式机（Windows 10/11），支持局域网手机访问

### 1.3 登录凭证（开发环境）

| 角色 | 账号 | 密码 | 说明 |
|------|------|------|------|
| **超级管理员** | `AT-admin` | `at123456` | 唯一内置账号，拥有全部功能权限，不可删除 |
| **学生** | `13812341234` | `123456789` | 测试学生账号 |
| **学生（备用）** | `13822222222` | `Student@123` | 备用测试账号 |

> 登录需要输入图形验证码（4 位数字），验证码显示在登录页面的图片上。
>
> **权限分级说明**：系统将 HR 账号分为两级——「超级管理员」（`admin` 角色）拥有所有功能；「HR 用户」（`hr` 角色）仅可访问「工作台」和「招聘管理」，无法进入「系统管理」。HR 用户账号由超级管理员在「系统管理 → HR账号」中创建。

## 二、系统安装与启动

### 2.1 环境要求

| 组件 | 版本 | 说明 |
|------|------|------|
| Java | 17+（Temurin JDK） | 后端运行必需 |
| Node.js | 18+ | 前端构建必需 |
| MySQL | 8.0 | 数据库，root 空密码 |
| Maven | 3.9+ | 项目自带，无需单独安装 |
| 操作系统 | Windows 10/11 64位 | 推荐配置：16GB 内存、SSD 硬盘 |

### 2.2 安装部署

项目根目录下的 `运维脚本` 文件夹提供了三个一键脚本：

| 脚本 | 用途 | 使用频率 |
|------|------|---------|
| **系统部署.bat** | 首次安装/重装系统时使用：环境检测 → 数据库初始化 → 后端编译 → 前端构建 → 目录创建 | 一次性 |
| **系统一键启动.bat** | 日常开机后使用：自动启动 MySQL → 后端 → HR 前端 → 学生前端 | 每天 |
| **系统停止.bat** | 停止所有服务 | 需要时 |

**首次使用步骤**：

1. 确保已安装 Java 17、Node.js 18、MySQL 8.0
2. 双击运行 `运维脚本\系统部署.bat`（约 5-10 分钟完成六阶段部署）
3. 双击运行 `运维脚本\系统一键启动.bat`（约 30-60 秒启动全部服务）
4. 浏览器访问 `http://localhost:5173`（学生端）或 `http://localhost:5174/admin`（HR 端）

### 2.3 服务端口

| 服务 | 端口 | 说明 |
|------|------|------|
| MySQL 数据库 | 3306 | 数据持久化存储 |
| 后端 API | 8080 | Spring Boot 应用 |
| 学生门户 | 5173 | Vite 开发服务器 |
| HR 管理后台 | 5174 | Vite 开发服务器 |

### 2.4 局域网手机访问

1. 确保手机与电脑连接同一 WiFi
2. 查看电脑局域网 IP（`设置 → 网络和 Internet → 属性 → IPv4 地址`）
3. 手机浏览器访问 `http://<电脑IP>:5173`（学生端）或 `http://<电脑IP>:5174/admin`（HR 端）

## 三、学生门户操作指南

### 3.1 首页

学生门户首页展示遨天科技品牌信息、在招岗位和公司介绍。页面从上到下包含：

- **企业精神**：团结、务实、厚德、尚道
- **口号**：赋能人类 太空活动
- **数据背书**：200+ 产品交付 / 5kW+ 最大功率 / 100% 自主研发 / LEO 轨道范围
- **在招岗位**：展示最多 3 个最新岗位
- **关于遨天**：公司简介 + 业务板块介绍

点击"查看在招岗位"或导航栏"岗位浏览"进入岗位列表。

### 3.2 注册与登录

1. 点击右上角"注册"按钮
2. 输入手机号 → 点击"发送验证码"（验证码显示在开发环境日志中）
3. 输入短信验证码、设置密码、勾选隐私政策 → 完成注册
4. 注册成功后自动登录，或使用手机号 + 密码登录

### 3.3 浏览与投递岗位

**岗位浏览**：

- 进入"岗位浏览"页面，查看全部在招岗位
- 支持关键词搜索、按部门/类别/地点筛选
- 点击岗位卡片查看详情

**投递流程**：

1. 在岗位详情页点击"投递简历"按钮
2. 选择要投递的简历附件（支持上传多个附件，投递时选择一个）
3. 选择投递渠道来源（官网/宣讲会/内推等）
4. 确认信息后提交

### 3.4 个人中心

登录后点击右上角用户名进入个人中心，包含以下功能：

| 功能 | 说明 |
|------|------|
| **基本资料** | 填写姓名、性别、出生日期、手机号、邮箱、现居城市、个人头像 |
| **教育经历** | 填写多段教育经历（学校/专业/学历/入学-毕业时间/GPA） |
| **简历附件** | 上传 PDF/Word 格式简历（≤10MB），支持在线预览和下载 |
| **实习/项目经历** | 填写实习或项目经历 |
| **技能证书** | 填写专业技能和获得证书 |
| **社团经历** | 填写学校社团活动经历 |
| **隐私设置** | 管理个人信息可见性和通知偏好、个人信息权利（导出/撤回同意/注销） |
| **账号安全** | 修改登录密码（需输入旧密码验证身份） |

> 个人中心的导航栏在各子功能间切换时保持常驻，无需返回首页重新选择，手机端可横向滑动切换。

**修改密码**：进入「账号安全」Tab，输入旧密码和新密码（新密码至少 8 位且须包含字母和数字），提交成功后系统自动登出并要求重新登录。

### 3.5 消息中心

登录后点击导航栏"消息"查看系统通知，导航入口显示未读消息数红点角标。通知类型包括：

- **投递成功通知**：提交投递后收到确认
- **简历状态更新通知**：HR 对简历进行「筛选通过」「已淘汰」等状态变更后，学生会收到「投递进度更新」消息，内容包含岗位名和最新状态
- **系统公告**

点击消息可查看详情；对「简历状态更新」类消息，可点击「查看投递进度」按钮直接跳转到对应投递记录查看当前状态。

### 3.6 我的投递

登录后点击导航栏"我的投递"查看已投递岗位的当前状态和历史记录。

## 四、HR 管理后台操作指南

### 4.1 工作台

登录 HR 后台后默认进入工作台页面，展示关键数据概览：

| 指标 | 说明 |
|------|------|
| 在招岗位数 | 当前状态为"已发布"的岗位总数 |
| 总投递数 | 系统内全部投递记录数 |
| 待筛选简历 | 状态为"待筛选"的简历数 |
| 本周新增 | 本周（周一至周日）新增投递数 |
| 筛选通过率 | 筛选通过数 / 总投递数 * 100% |
| 最近投递动态 | 最新 5 条投递记录 |

### 4.2 岗位管理

**功能入口**：招聘管理 → 岗位管理

**主要操作**：

| 操作 | 说明 |
|------|------|
| **创建岗位** | 填写岗位名称、部门、类别、地点、学历要求、招聘人数、截止日期、富文本 JD 描述 |
| **编辑岗位** | 修改已有岗位信息 |
| **上架/下架** | 控制岗位在门户的显示状态 |
| **到期自动下架** | 截止日期过后系统自动将岗位下架（每 5 分钟检查一次） |

**岗位模板**：在"岗位模板"中预设常用岗位信息，创建岗位时可快速套用模板。

### 4.3 简历管理

**功能入口**：招聘管理 → 简历管理

**简历列表**：

- 支持多条件筛选：关键词（姓名/学校）、岗位、状态、学校、专业、学历、投递时间范围
- 列表显示：姓名、学校、专业、学历、投递岗位、投递时间、当前状态
- 支持排序：按学校、专业、投递时间排序
- 勾选简历后可进行批量操作

**简历详情**：

点击简历进入详情页，左侧展示：

- 基本信息（姓名/手机/邮箱/学校/专业/学历）
- 教育经历列表
- 投递信息（岗位/来源/时间/状态）
- HR 内部备注（可添加）

右侧展示简历附件 PDF/Word 在线预览（支持全屏查看和翻页）。

**简历筛选**：

- **通过**：单条通过或批量通过，简历状态变为"筛选通过"
- **淘汰**：单条淘汰或批量淘汰，简历状态变为"已淘汰"
- 支持 5 分钟内撤销误操作
- 状态变更后系统自动向学生发送站内信通知（详见「六、候选人状态流转」）

**导出 Excel**：

1. 在列表中勾选要导出的简历
2. 点击"导出 Excel"按钮
3. 浏览器自动下载 `简历导出_<HR姓名>_<日期>.xlsx` 文件

导出文件包含：姓名、学校、专业、学历、手机号（脱敏）、投递时间、当前状态。单日导出上限 2000 条。

### 4.4 学生管理

**功能入口**：招聘管理 → 学生管理

**列表功能**：查看学生账号信息（手机号/姓名/毕业院校/专业/注册时间/状态/投递数），支持按毕业院校、专业、注册时间排序。

**学生详情**：点击列表中的学生行或"详情"按钮查看完整信息：

- 基本信息（姓名/性别/手机号/邮箱/出生日期/所在城市/注册时间/账号状态）
- 教育经历
- 实习/项目经历
- 简历附件
- 投递历史（最近 5 条）

**操作**：启用/禁用学生账号、删除学生账号（逻辑删除）。

> 学生详情页的每次查看都会记录到操作审计日志中，满足个人信息保护法合规要求。

### 4.5 数据报表

**功能入口**：招聘管理 → 数据报表

| 报表 | 说明 |
|------|------|
| **投递趋势** | 按日期显示投递数量曲线图 |
| **学校分布** | 投递学生来源学校排名 |
| **学历分布** | 投递学生学历构成饼图 |
| **岗位投递排行** | 各岗位收到投递数量排名 |
| **渠道来源** | 投递渠道来源分布统计 |

所有报表支持按日期范围筛选。

### 4.6 岗位类别

**功能入口**：招聘管理 → 岗位类别

管理岗位的分类体系，支持两级分类：

- **一级类别**：硬件研发、软件研发、职能
- **二级类别**：硬件研发下设电源、结构、控制、测试、工艺等子类别

每个类别可设置启用/禁用状态（点击状态标签即可切换）。

### 4.7 个人中心

**功能入口**：右上角用户名下拉菜单 → 个人中心

所有 HR 账号（超级管理员和 HR 用户）均可使用个人中心，包含两个标签页：

| 标签页 | 说明 |
|--------|------|
| **个人信息** | 查看/编辑本人昵称、邮箱、手机号、性别 |
| **修改密码** | 输入旧密码验证身份后设置新密码（至少 8 位且须包含字母和数字），修改成功后自动登出需重新登录 |

> 个人中心仅能修改「本人」信息，无法修改用户名、角色、部门等身份字段。

## 五、系统管理端操作指南

> 本章功能仅「超级管理员」（`admin` 角色）可见和可操作。「HR 用户」（`hr` 角色）登录后不显示「系统管理」菜单，也无法通过直接访问 URL 调用系统管理接口（后端已做权限兜底拦截）。

### 5.1 HR 账号管理

**功能入口**：系统管理 → HR 账号

管理可登录 HR 后台的账号，包括：

- 新增/编辑/删除 HR 账号
- 分配角色（超级管理员 `admin` / HR 用户 `hr`）
- 设置所属部门
- 启用/禁用账号
- 重置密码

> HR 账号列表新增「角色」列，显示每个账号绑定的角色（超级管理员 / HR用户 / 未分配）。

### 5.2 角色管理

**功能入口**：系统管理 → 角色管理

系统预置两个角色，对应两级权限：

| 角色 | 角色标识 | 权限范围 | 说明 |
|------|---------|---------|------|
| **超级管理员** | `admin` | 工作台 + 招聘管理 + 系统管理 | 拥有全部功能，可查看所有岗位的所有简历，可修改系统配置 |
| **HR 用户** | `hr` | 工作台 + 招聘管理 | 仅可访问招聘业务功能，不可进入系统管理，仅可查看自己负责岗位的简历 |

> 在「新增角色」时，权限字符只能从 `admin` 或 `hr` 下拉选择，不能自由填写。

### 5.3 部门管理

**功能入口**：系统管理 → 部门管理

维护公司组织架构树，用于岗位归属和 HR 账号归属。

### 5.4 字典管理

**功能入口**：系统管理 → 字典管理

维护系统下拉选择项的数据字典，包括学历、性别、渠道来源等选项的值和标签。

### 5.5 品牌配置

**功能入口**：系统管理 → 品牌配置

可配置学生端门户的品牌展示信息：公司名称、Logo、品牌色、联系邮箱、版权信息、Banner 图片、公告内容等。配置项以 Key-Value 形式存储，实时生效。

> 品牌配置原位于「招聘管理」，V3.0 起迁移至「系统管理」，仅超级管理员可访问。

### 5.6 通知模板

**功能入口**：系统管理 → 通知模板

管理系统自动发送通知的模板内容（站内信/短信/邮件）。可模板中插入变量占位符（如 `{学生姓名}`、`{岗位名称}`）。

### 5.7 操作审计

**功能入口**：系统管理 → 操作审计

查看 HR 的操作记录，包括：

- 简历查看记录（操作人、查看的学生、操作类型、IP 地址、时间）
- 学生详情查看记录
- 网络配置变更记录

支持按操作类型、操作人筛选。

### 5.8 网络管理

**功能入口**：系统管理 → 网络管理

管理系统的跨域访问白名单和网络配置（仅超级管理员可访问）：

| 标签页 | 说明 |
|--------|------|
| **CORS 白名单** | 管理允许跨域访问系统 API 的来源地址（Origin），支持精确域名和 CIDR 网段（如 `192.168.31.0/24`） |
| **局域网访问** | 控制是否允许局域网设备直连系统 |
| **网络诊断** | 查看当前监听地址/端口、生效的白名单、请求来源 IP、是否经过 Nginx 转发等诊断信息 |
| **变更历史** | 查看网络配置的变更记录（谁在什么时间改了什么值） |

**典型使用场景**：HR 需要手机连 WiFi 访问后台 → 在网络管理中新增手机所在网段的 CIDR 规则 → 手机即可访问。

## 六、候选人状态流转

### 6.1 状态说明

| 状态 | 英文码 | 含义 |
|------|--------|------|
| 待筛选 | `PENDING_SCREEN` | 学生投递后的初始状态 |
| 筛选通过 | `SCREEN_PASSED` | HR 评审后认为符合要求 |
| 已淘汰 | `ELIMINATED` | HR 评审后认为不符合要求 |
| 待面试 | `PENDING_INTERVIEW` | 进入面试安排环节（二期） |
| 面试中 | `IN_INTERVIEW` | 面试进行中（三期） |
| 面试通过 | `INTERVIEW_PASSED` | 面试合格（三期） |
| 待录用 | `PENDING_OFFER` | 进入 Offer 阶段（三期） |
| 已发 Offer | `OFFER_SENT` | Offer 已发送（三期） |
| 已接受 | `ACCEPTED` | 学生接受 Offer（三期） |
| 已拒绝 | `REJECTED` | 学生拒绝 Offer（三期） |
| 已入职 | `ONBOARDED` | 学生入职报到（三期） |

### 6.2 一期已实现的状态流转

```
投递成功 → 待筛选
待筛选   → 筛选通过（HR 通过）
待筛选   → 已淘汰  （HR 淘汰）
筛选通过 → 已淘汰  （HR 淘汰）
```

### 6.3 状态变更消息通知

HR 对简历执行「筛选通过」「已淘汰」等状态变更操作后，系统会**自动向学生发送站内信通知**，学生端消息中心显示「投递进度更新」消息，内容包含岗位名和最新状态。

- 消息类型：`APPLICATION_STATUS_CHANGED`（简历状态变更）
- 触发场景：简历筛选通过、筛选淘汰、手动状态流转
- 幂等保证：同一次状态变更只发送一条消息（通过 `dedup_key` 唯一索引防重）

## 七、常见问题

### 7.1 验证码不显示

**原因**：后端服务未运行或 MySQL 未启动。

**解决**：双击运行 `运维脚本\系统一键启动.bat`，等待全部服务就绪后刷新页面。

### 7.2 页面加载失败/网络错误

**可能原因**：

1. 后端服务未启动 → 检查 8080 端口是否监听（`netstat -ano | findstr :8080`）
2. MySQL 未启动 → 检查 3306 端口
3. 前端 Vite 代理未配置 → 确认通过 5173/5174 访问而非直连 8080

### 7.3 手机无法访问

1. 确认手机与电脑在同一 WiFi
2. 确认电脑 IP 地址（`ipconfig` 查看）
3. 进入系统管理 → 网络管理 → CORS 白名单，添加手机所在网段的 CIDR 规则（如 `192.168.31.0/24`）
4. 手机浏览器访问 `http://<电脑IP>:5173`

### 7.4 筛选通过率显示为 0

**原因**：系统使用精确状态码匹配（如 `SCREEN_PASSED`），如果报表页面请求时传了缩写码（如 `PASSED`），后端查不到匹配记录。

**解决**：此问题已在 V2.1 修复，`SCREEN_PASSED` 对应的数据会自动正确计算。

### 7.5 岗位类别全部显示"禁用"

**原因**：种子数据中类别状态字段初始值为 `0`（禁用）。

**解决**：此问题已在 V2.1 修复，新部署的环境不会再出现。已有环境影响的数据可通过 SQL `UPDATE job_category SET status='1'` 修复。

### 7.6 导出 Excel 失败

**原因**：导出功能使用了前后端要求不一致的 API 响应处理方式。

**解决**：此问题已在 V2.1 修复，点击导出后浏览器应自动下载 `.xlsx` 文件。如果仍失败，按 F12 打开控制台查看具体错误信息。
